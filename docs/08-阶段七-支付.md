# 阶段七:支付

> 目标:订单状态机 10→20 的迁移(支付成功),模拟支付网关 + 回调幂等 + 支付流水。
> 核心命题:**回调驱动的状态迁移怎么做到「恰好一次生效」**。

## 1. 为什么支付是「同步强一致」而不是 MQ 异步

对比下单:下单走 MQ 排队,用户能接受「排队中」;支付**必须立即知道结果**(用户付了钱,界面要马上显示成功)。支付流量远小于下单,不需要削峰。

> 设计原则:**吞吐敏感走异步(下单),结果敏感走同步(支付)** —— 同一个系统,不同路径选不同一致性模型,按业务语义选,不教条。

## 2. 模拟支付网关(方案选择)

**方案 A:纯内部模拟**——点支付直接改状态。简单,但「回调/幂等/流水」全部体现不出来,失去学习价值。

**方案 B:模拟支付网关(选择它)**——结构对齐真实支付宝对接:

```
用户点支付 → 创建支付单(待支付)
  → 「模拟网关」处理(真实场景:跳转支付宝页面)
  → 网关回调我方接口 POST /api/pay/notify(真实场景:支付宝异步通知)
  → 验签(模拟)→ 订单 10→20 + 支付单完成
```

真实世界的三个关键点全部保留:**回调入口、回调幂等、支付流水**。将来换支付宝沙箱,只换「模拟网关」那一层。

## 3. 支付流水表 pay_record

```sql
CREATE TABLE pay_record (
  id          BIGINT NOT NULL,
  pay_no      VARCHAR(32) NOT NULL COMMENT '支付单号(对用户)',
  order_id    BIGINT NOT NULL COMMENT '关联订单',
  amount      DECIMAL(10,2) NOT NULL,
  status      TINYINT NOT NULL DEFAULT 0 COMMENT '0待支付 1成功 2失败',
  pay_time    DATETIME DEFAULT NULL,
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_pay_no (pay_no),
  UNIQUE KEY uk_order (order_id)     -- 一个订单只有一张支付单
) COMMENT='支付流水表';
```

## 4. 核心链路与三处幂等

```
POST /api/order/pay?orderId=
  ① 校验:订单归属 + status=10(不是待支付 → 409)
  ② 建支付单(pay_no, status=0)——uk_order 唯一:重复点支付撞唯一键 → 直接返回已有支付单(幂等1)
  ③ 模拟网关支付(真实场景:跳转 + 用户输密码)
  ④ 回调 handlePayNotify(payNo):
     事务内:
       · 订单 10 → 20(WHERE status=10 条件更新 ← 幂等2:重复回调第二次 0 行)
       · 支付单 0 → 1(WHERE status=0 条件更新 ← 幂等3)
       · pay_time = now
     任一步 0 行受影响 → 说明已处理过 → 直接返回(重复回调无害)
```

**三处幂等的层次**:幂等1 挡「重复点支付」,幂等2 挡「重复回调」,幂等3 是流水自己的防线——和阶段四/六的「入口判断 + 条件更新」同一个范式,第四次实战。

## 5. 与阶段六的联动:支付后闹钟作废(验收亮点)

支付成功后订单 status=20,闹钟(延迟消息)到点时:

- OrderTimeoutConsumer 查订单 → status=20 ≠ 10 → 作废,什么都不做 ✓

**阶段六埋的「作废」逻辑在阶段七第一次被真实触发**——用「下单 → 支付 → 等闹钟 → 订单依然是 20」做验收,两个阶段闭环。

## 6. 任务清单

1. **pay_record 表 DDL + PayRecord 实体 + Mapper**
2. **PayService**:
   - `createPayment(orderId, userId)`:归属校验 + status=10 校验 → 建支付单(uk_order 冲突则返回已有)→ 模拟网关 → 回调
   - `handlePayNotify(payNo)`:事务内订单 10→20 + 支付单 0→1 + pay_time,幂等返回
3. **接口**:
   - `POST /api/order/pay?orderId=`(走网关,带 X-User-Id)
   - (可选)`GET /api/pay/status?payNo=`
4. **验收**:
   - 下单 → 支付 → 订单 20 + 支付单 1 + pay_time 非空
   - 重复点支付 → 幂等,返回同一支付单
   - 支付已取消订单 → 409
   - **支付后等闹钟 → 订单仍是 20(闹钟作废,阶段六联动)**
   - 手动重复调回调 → 无副作用
